# Spool — Shared Filament Tracker

A household filament tracker for a shared 3D printer, with three accounts:
**Vidar**, **Lukas**, and **Vincent**. Members contribute filament (credited as
grams), spend those grams when they print, and owe cash to whoever's spool
they printed from once their own gram balance runs out.

## Stack

- **Backend**: FastAPI + SQLModel (SQLite), JWT sessions, all endpoints behind
  a shared `X-API-Key` header.
- **Frontend**: React + Vite + Tailwind + daisyUI.
- **Docker Compose**: two separate stacks — `docker-compose.dev.yml` (local,
  live-reloading) and `docker-compose.prod.yml` (static build + Cloudflare
  tunnel).

## Config files

- `.env` (project root) — `API_KEY`, `SECRET_KEY`, `CURRENCY`,
  `CLOUDFLARE_TUNNEL_TOKEN`. Loaded by Docker Compose to fill in
  `${VAR}` placeholders in the compose files. Gitignored.
- `secrets/tempPass_<account>` — one plain file per account holding a bcrypt
  password hash, generated by `scripts/hash_password.py`. Kept out of `.env`
  on purpose: Compose does shell-style interpolation on env var values, and a
  bcrypt hash's literal `$` characters get silently mangled by that. Gitignored.

Neither has a `.example` template checked in — this is a household setup for
three specific people, not something meant to be cloned and reconfigured, so
the real files are what you edit directly.

## First-time setup

1. `.env` needs `API_KEY` and `SECRET_KEY`. Generate values with:

   ```bash
   openssl rand -hex 32
   ```

2. Set a password for each account. This hashes a password with bcrypt and
   writes it straight to `secrets/tempPass_<account>` — the plaintext
   password is never written to disk. Run it in your own terminal (not
   piped, not pasted into a shared session), once per account:

   ```bash
   docker compose -f docker-compose.dev.yml run --rm --build backend python scripts/hash_password.py
   ```

   It asks which account (`vidar`, `lukas`, or `vincent`) and prompts for a
   password twice. If that account's file already exists, it refuses to
   overwrite it — delete `secrets/tempPass_<account>` yourself first if you
   want to change a password. Restart the backend afterwards for it to pick
   up the change.

3. For production, paste your Cloudflare tunnel **connector token** into
   `.env` as `CLOUDFLARE_TUNNEL_TOKEN`. Get it from Cloudflare Zero Trust →
   Networks → Tunnels → your tunnel → Configure → Install and run a
   connector. It's a long base64 string, not the tunnel's UUID. Point the
   tunnel's public hostname at `frontend:80` (the internal docker network
   address).

   Starting the prod stack brings this tunnel up live and connects it to
   Cloudflare's edge immediately — if a public hostname is already routed to
   it, the app becomes internet-reachable the moment the container starts.

## Running it

**Local development** — backend reloads on save, frontend has Vite HMR, no
tunnel:

```bash
docker compose -f docker-compose.dev.yml up --build
```

Backend: http://localhost:8005/api · Frontend: http://localhost:5173

**Production** — static frontend build served by nginx, backend, and the
Cloudflare tunnel:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Frontend: http://localhost:8004 (and whatever hostname you configured in
Cloudflare, once the tunnel connects).

## Local development without Docker

Backend:

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload
```

It reads `backend/.env` for `API_KEY`/`SECRET_KEY`/etc, and password hashes
from `../secrets/tempPass_<account>` (same files Docker uses).

Frontend:

```bash
cd frontend
npm install
npm run dev
```

The Vite dev server proxies `/api` to `http://localhost:8000` by default
(see `vite.config.js`) — set `VITE_API_KEY` to match the backend's `API_KEY`.

## How the model works

- Each member has a **gram balance** (grams of filament they've contributed
  to the shared pool) and a running total of **grams printed**.
- Filament **spools** in the library are tracked separately, each with an
  owner, price per kg, and grams remaining.
- Logging a print deducts grams from the printer's own gram balance first;
  any shortfall is charged as cash owed to the spool's owner
  (`shortfall_grams × price_per_gram`), tracked until marked paid.
- "Add filament" (crediting a member) and "Add filament" (adding a new spool
  to the library) are two distinct actions — the former tops up a member's
  spendable gram balance, the latter adds physical stock.

## Security notes

- `X-API-Key` gates every API request — this is a shared secret for anyone
  reaching the tunnel, not per-user auth.
- Per-user login checks against `secrets/tempPass_<account>` and issues a
  30-day JWT identifying who's using the app.
- The API key is baked into the frontend JS bundle at build time (it has to
  be, since this is a static site) — treat it like the household door key,
  not a secret that survives a determined attacker. Fine for a personal
  Cloudflare tunnel shared with three trusted people; don't reuse it
  elsewhere.
